## 최신 선택: 짧은 원음에서만 L3,2 추가 — 실행 보류

사용자 최종 선택은 원음 **2초 이하**인 정상에만 **3초–2초 BPL**을 추가하는 것이다. 기존4초–3초 BPL과 OC는 유지한다. 기존0.5/0.5비중을 이어 적용하면 짧은 원음 묶음은 `OC+0.5L4,3+0.5L3,2`, 나머지는 `OC+L4,3`이다. 이는 단순히 기존L4,3에 계수1의 새 손실을 더하는 구성과 다르다.

- 4초/3초는 기존64,600/48,440samples, 2초는32,000samples(16kHz)다. 부족하면 반복한다.
- L3,2는 해당 짧은 정상 묶음의3초 view×2초 view 전체 양성쌍을 기존BPL수식으로 평균한다. 같은UID대각선만 비교하는 것으로 바꾸지 않는다.
- L4,2·삼중텐서손실·BPL1은 추가하지 않는다. 기존BPL과 같은 양방향 역전파를 기본으로 하고, 별도stop-gradient변경은 넣지 않는다.
- 구현에서는 기존클래스별DistributedSampler와짧은loader순환·부분배치를유지한다. 추가길이재묶기/50:50재표집은없다. 혼합배치의정상N개중대상K개에만4–3항의anchor비중을절반으로줄이고,3–2항은K×K평균에K/(2N)을곱한다. 나머지원음의기존BPL43은그대로다.
- 원음≤2초는 정상109/2580개다. 세 고정길이는 같은 원음 정보를 반복하므로 2초추가가 새로운 독립음성정보를 늘리는 것은 아니다. 정상오류와 함께 짧은스푸프·A10/A11누락을 검사한다.
- **새실험실행은계속보류**다. 이전5/4-4/3코드초안은이3/2설계를구현하지않으며그코드로대신실행하지않는다.

상세기록: [설정·결과 근거](../../artifacts/bpl_three_view_design_20261111/selected_short32_plan.json).

### 구현·검증 기록

최신 실행 경로는 [실험 구현·검증 소스](../../../../../short32_original240.py)다. 원본 소스5개를 [manifest](../../../../../baseline240_source/manifest.json)로 검증하며 원래 두 DataLoader와 full-graph `ModelTrainer.train`을 그대로 호출한다. Dataset의3값 출력, 각 클래스 sampler, 작은loader순환, 부분배치, 독립RawBoost, backend→OC중심의두단계Adam은 유지한다. 이전 합성batch/replay 경로는 실행 경로에서 제거했다.

정상 원음 길이와 원본 sampler 순서를 읽기 전용으로 대응해 추가손실 대상을 판정한다. 추가2초view는 이미 증강된 원래3초view의 앞32,000sample이다. 추가backend난수는 별도fork_rng로 분리해 원래4/3·OC중심·worker seed의 흐름을 보존한다.

혼합배치에서 A=기존전체L43, A_E=대상4초anchor행×전체3초열의 평균, B=대상3초×대상2초전체쌍 평균이면 `L=OC+A-(K/(2N))*A_E+(K/(2N))*B`를 사용한다. 기존0.5/0.5선택을 유지하며 K=0이면 원본과 정확히 같고 K=N이면0.5/0.5다.

[검토용 전체 변경 설명](../../../../../SHORT32_ORIGINAL240.md) · [새 검증 결과](../../artifacts/short32_robustness_20261111/final/validation.json) · [최신 상태](../../artifacts/short32_robustness_20261111/state.json).

앞선38검사는 이전 구현의 기록이며 현재 구현 검증과 혼동하지 않는다. 실제연구실음성/XLS-R/GPU통합 및 EER개선은 이번 검증의 범위가 아니다. 기존109개 대상/Train메타데이터 결과는 보존하되 학습 결과로 해석하지 않는다.


## 이전 사용자 선택: 조건부5/4·4/3 후보

사용자는 반복 사용과 **OC + 0.5 기존 BPL + 0.5 BPL2**를 선택했다. BPL1은 이번에 적용하지 않는다. 새 모델을 seed1, 50epoch 학습한다.

| 원음 길이 기준 | BPL2 긴 입력 | BPL2 짧은 입력 |
|---|---:|---:|
| 기존 long보다 김: 원음 >64,600 samples | 80,000 samples = 5초 | 64,600 samples ≈4초 |
| 원음 ≤64,600 samples | 64,600 samples ≈4초 | 48,440 samples ≈3초 |

16kHz 기준이다. 기존 long/short 상수 64,600/48,440을 유지하므로 정확히 4.000/3.000초라고 표기하지 않는다. 길이가 부족하면 사용자 지시대로 wrap 반복한다. 특히 4.0375~5초 원음도 5초 입력에서는 일부 반복한다. 자연적으로 짧은 원음의 BPL2 입력 역시 반복해서 목표 길이를 맞춘다. 이전 후보의 ‘짧은 student는 반복하지 않음’은 **이번 실험에는 적용하지 않는다**.

### 섞어서 학습하는 방식

- 긴 원음/짧은 원음을 별도 모델이나 별도 학습 단계로 나누지 않는다.
- 기존 클래스별 OC sampler와 원음 방문 순서를 유지한다. 매 원음의 길이에 따라 BPL2 쌍만 선택한다.
- 두 쌍 종류를 순서대로 번갈아 50:50으로 만들지 않는다. 정상 Train 2,580개 중 원음 >long은 576개(22.33%), 나머지는 2,004개(77.67%)다. 50:50 강제는 긴 원음의 추가 재표집 효과를 만든다.
- 쌍의 처리 순서는 무작위여도 된다. UID 대응과 긴 참조/짧은 student 역할을 유지한다. BPL2에서 다른 원음끼리 섞어 전쌍 비교하지 않는다.
- BPL2는 정상의 같은 원음 쌍만 비교한다. 기존 BPL은 원래의 정상 long×short 전체 쌍이다.

### 고정할 항목

- OC: 기존 약4초 입력, 정상/스푸프 모두 같은 기존 반복 정책, 원래 클래스 가중치.
- 기존 BPL: 원래 약4초/약3초 view 및 독립 RawBoost, GPU당 정상12×12쌍(부분 배치는 실제 정상 수의 제곱).
- BPL2: 같은 UID의 조건부 5/4 또는4/3쌍, 정상 anchor당 한 쌍. 긴 참조 embedding은 stop-gradient, 짧은 쪽에만 직접 역전파한다. 별도 teacher 모델은 없다.
- BPL2 짧은 입력은 긴 입력 안의 연속 구간으로 만든다. 가능한 경우 인위적 반복 경계 없이 원래 구간 안에서 선택한다. 증강 파형의 해당 구간을 그대로 잘라 길이 외 차이를 줄인다.
- 기존 RawBoost0~8 유지, codec/speed/tempo 증강·새 VAD 재표집 정책 없음. 속도 0.8~1.2배·최대 20% 절단 변형 변형 캐시를 이 실험의 학습 원음으로 사용하지 않는다.
- global OC batch240, GPU당 정상12/스푸프108, 동일 원음 sampler·부분 배치·optimizer두 단계·frozen XLSR·lr1e-5·원래 scheduler 유지.
- 추가 view는 OC 배치를 늘리는 것이 아니다. 실제 파형 수/프레임/메모리는 별도로 기록한다.
- BPL 계수는 처음부터 0.5/0.5. 종합 후보의 0.75/0.25와 warm-up 제안은 이번에 자동 적용하지 않는다.

### 비교와 판정

dev 새 평가는 없다. checkpoint5/10/.../50은 평가 전에 원자적으로 저장하고, 19LA 중간 평가와 학습 후 전체 checkpoint의21LA/DF 평가에서 최소 EER와 해당 epoch를 보고한다. 고정50도 보조 보고한다. 데이터셋별 target 최소는 사후적인 최솟값이며 독립적인 배포 모델 선택 성능이 아니다.

주 평가는 앞64,600cap/비반복/mask/batch8/seed1729/학습 OC중심 cosine/원래 ASP잡음1e-5로 통제한다. 반복에 대한 입력 진단은 별도 noise0 조건으로 구분한다. 길이별 정상 오탐과 스푸프 누락, A10/A11·코덱별 결과를 함께 확인한다. 정상 점수만 올라가고 스푸프 누락이 늘면 성공으로 판단하지 않는다.

현재 실행 중인 반복 진단은 중단하거나 변경하지 않는다. 새 실험은 동일 컨테이너/GPU6·7 실제 유휴와 기존 작업 성공 종료를 확인한 뒤 실행한다. 새 유료자원/지출상한0USD, 자동재시도0, 고유 실행 root·소스/모델 SHA·검사·종료 기록을 보존한다. 실제 작업 상태는 `../../artifacts/bpl2_conditional_54_43_20261111/`의 상태 파일이 기준이다.

## 이전 종합 후보: OC + BPL1 + BPL2

이 절은 사용자가 먼저 Markdown으로 저장해 달라고 한 종합 설계의 보존본이다. 세부 기계 판독 명세는 [설정·결과 근거](../../artifacts/bpl1_bpl2_final_design_20261111/specification.json)에 있다.

### OC

배치 240 고정 길이 반복 입력 학습의 정상/스푸프 판별을 유지한다. OC 입력 분포까지 강제로 짧게 바꾸지 않는다. 원래 정상/스푸프 클래스 배치, OC 중심과 두 단계 Adam, frozen SSL을 유지한다.

### BPL1: 같은 화자의 다른 정상 발화

정상 anchor마다 같은 화자·다른 UID의 정상 발화 하나를 선택한다. 네트워크 입력 길이를 맞추고 원래 유효 길이 비율도 min/max≥0.8로 맞춰 반복 정도의 차이를 줄인다. 각 view에는 기존 RawBoost를 독립 적용한다. 양쪽에 역전파하고 codec은 사용하지 않는다.

화자 ID는 학습 쌍 선택에만 사용한다. 같은 화자 양성쌍은 화자 정보 제거와 같지 않다. 화자별 군집이나 채널 편향이 강해질 위험을 측정해야 한다. 메타데이터상 정상2,580개 중2,579개가 조건을 만족하는 상대가 있고, 상대 수 중앙값은77개다. 발화량 조건까지 통과한다는 뜻은 아니다. 상대가 없으면 해당 BPL1만 건너뛰며 OC 원음을 버리지 않는다.

### BPL2: 같은 원음의 내용이 겹치는 길이 변화

이전 보수적 후보는 2초 이상 원음에 대해 유효 구간의80~90%를 보존하는 연속 crop, 2초 미만 원음은 전체 사용을 제안했다. student는 비반복 실제 길이와 mask를 사용하고, 긴 OC 참조를 detach한다. 발화량80% 보존은 추가 검사 제안이며 실제 Train 전수 검증은 아직 하지 않았다. 시간/발화량 보존이 모든 음성 정보 보존을 보장하지 않는다.

이전 종합 후보의 최종 목적식은 `OC +0.75BPL1 +0.25BPL2`였다. 최초5epoch 기존BPL 이후6~10epoch에서 전환하는 common warm-up과5개 통제 학습 조건(A144/A12/BPL1교체/BPL2교체/결합)을 제안했다. 이는 검증된 최적 계수·성능이 아니라 검증할 후보이다. **이번 첫 실험은 위 사용자 선택으로 이를 변경한다.**

### 쌍 수와 입력 순서

기존BPL은 `mean softplus(30*(1-cos))-0.3`의 전체12×12평균이다. 동일한 두 묶음의 순서만 바꾸면 평균이 변하지 않는다. BPL1/BPL2를 구분하려면 쌍 mask, 묶음별 호출 또는 명시적 대응이 필요하다. 원래144쌍과 anchor당1쌍은 다른 설정이므로 쌍 수 통제 A12가 필요하다. 양성 일관성만으로 정상/스푸프 분리를 증명할 수 없으므로 OC를 유지한다.

## 분석·연구 근거

- 완료된 길이·음성활동·원음 전수 노출을 맞춘 20epoch 학습은 목표 입력의80%가2초 이하인 강한 단문 정책이었다. 길이 보정 후에도 성능 저하가 남았고 A10/A11의 문제가 같은 길이 안에서도 관측됐다. 이를 ‘크롭이 원인’이라는 단일 인과 결론으로 취급하지 않는다.
- 배치 240 고정 길이 반복 입력 학습 보관 소표본의21LA<2초 정상오류는 비반복3/32→반복8/32, 스푸프 누락은6/32→0/32였다. 반복은 양쪽을 스푸프 방향으로 밀었다. 새로운 전체 반복·dose진단 결과와 구분한다.
- Train2초 이하 비율은 정상4.22%/스푸프14.07%지만, long반복 필요 비율은 정상77.67%/스푸프72.83%다. 반복 여부와 반복 정도를 구분해야 한다.
- [EBM, Interspeech2025](https://www.isca-archive.org/interspeech_2025/kim25g_interspeech.pdf): Sec3.1·4·5.2/Table2 확인. EOC-S에BPL 추가 시21LA1.41→1.21%, DF2.12→1.89%. 논문 대응 쌍과 로컬 전체쌍 구현, 배치·학습량 차이를 구분한다.
- [AASIST2](https://arxiv.org/pdf/2309.08279): Sec2.2·4/Table1 확인. DCS의4초평가 LA1.76→1.08%, DF4.38→7.14%. 길이 변형의 효과가 데이터셋별로 다르다.
