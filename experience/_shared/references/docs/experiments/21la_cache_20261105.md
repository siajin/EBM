# ASVspoof 2021 LA 임베딩 캐시 추가

2026-11-05 **11:29 KST 완료**. 사용자 요청에 따라 기존 T/V/DF 캐시에 21LA 공식 eval 전체를 추가했고, 로컬 저장·독립 검수·기존 데이터와의 재계산까지 통과했다.

## 데이터와 모델

- 공식 21LA metadata 181,566행 중 `eval`인 **148,176개 전체**를 사용한다. `progress` 16,464개와 `hidden` 16,926개는 제외한다.
- 정상 **14,816개**, spoof **133,360개**. 화자67그룹, spoof 공격13종, codec7종이다. 발화ID 중복0, 누락 음성0, 미상 화자0을 확인했다.
- 원래 보관된 21LA evaluator의 label 규칙과 metadata label의 일치도 확인했다. 데이터 sampling이나 checkpoint 선택은 하지 않는다.
- 기존 기준 `EBM_e50_bs160_lr1e5`의 epoch50 checkpoint를 고정한다. SHA256은 `104873703a57cad98b686d770e0860e031a2cf9abef79b72668780c1660e0b24`다.
- frontend는 기존 offline XLS-R, 입력은16kHz mono 64,600sample이다. 원래 평가 loader의 앞 구간 crop/wrap padding을 그대로 사용한다.
- 저장값은 long-view h/z 각160차원, 정규화 centroid, native 점수, codec·transmission·화자·공격·길이·padding 등의 파생 metadata다. 원음·원본 연구 코드·checkpoint·원래 경로 포함 manifest는 로컬 전송 대상이 아니다.

## 추출과 검수

기존 컨테이너 `3b9cf2ce426f`의 유휴 screen0을 확인하고 `CUDA_VISIBLE_DEVICES=0,1`로 실행한다. 기존 학습·결과·소스는 변경하지 않는다. 새 EBM 학습이나 probe fit은 없다.

1. manifest·원래 코드/모델·자체 추출 코드 hash를 고정한다.
2. 정상32/spoof96개 QC에서 기존 단일 발화 frontend+classifier 전체 forward와 비교한다. z/h/score 최대 절대 오차 기준은 각각 `1e-5`다.
3. 동일 발화 반복 및 GPU 간 z 일치도 검사한다.
4. QC가 통과한 경우에만 전체148,176개를 추출한다.
5. 전체 행·유한값·160차원·native cosine 대응·ID/rank 정렬을 검사하고 완료 marker 및 종료코드0을 요구한다.
6. 완료된 파생 파일만 SFTP로 받고 파일별 SHA256을 대조한 후 로컬에서 native 지표를 다시 계산한다.

## QC에서 확인한 사항

설치된 Transformers의 Wav2Vec2 encoder는 eval에서도 layer마다 CPU `torch.rand([])`를 호출한다. 값 자체는 eval에서 layer를 생략하지 않지만, 이후 ASP의 CPU 잡음 생성에 영향을 준다. 단일 발화 seed를 그대로 보존하려면 이 난수 상태의 진행도 재현해야 한다.

- `20261105_21la_full_01`: 최초 묶음 처리 검수에서 이 CPU RNG 진행 검사가 실패했다. 전체 추출은 시작하지 않았다.
- `20261105_21la_full_02`: RNG 진행을 맞춘 뒤에도 batch16과 원래 단일 발화의 z 최대 오차가 `1.58548e-5`로 기준을 넘었다(h `3.68804e-7`, cosine `4.22178e-6`). 이 묶음 방식은 사용하지 않는다.
- `20261105_21la_full_03`: 원래 단일 발화 kernel shape를 유지하고 frozen SSL 부분만 CUDA graph로 호출한다. classifier는 발화별 eager 실행과 원래 ASP 난수를 유지한다. 그래프의 CPU RNG 생략분은 실제 encoder layer 수만큼 scalar draw를 재생하고 검증한다. **QC128개에서 원래 단일 발화 대비 h/z/score 오차가 모두0**으로 통과해 이 방법으로 전체를 추출했다.

실패한 QC 경로는 보존한다. 실행 중인 작업을 중단하거나 같은 결과 폴더를 지우고 재실행하지 않는다.

## 캐시 접근

완료된 캐시의 별칭은 **`21LA_eval`**이고 내부 split은 `R21LA`다.

```python
from artifacts.geometry_experiments.geometry_cache import load_embeddings, validate_run

validate_run("21LA_eval")
data = load_embeddings("21LA_eval")
# data.z / data.h: [148176, 160]
```

미완료 상태에서는 API가 접근을 거부한다. 동기화는 부분 memmap을 가져오지 않으며 완료 전 `not_ready`를 기록한다. `analyze_geometry_cache.py`는 준비된 catalog 데이터셋을 기본으로 재계산하므로 완료 후 21LA도 포함한다.

현재 로컬 폴더는 `artifacts/geometry_cache/runs/20261105_21la_full_03/4110118cb92e35c1/`이다. fingerprint는 `4110118cb92e35c171ef7b71194407b5a3400b5d3eedaeb2af9909c096997a29`다.

화자는 `asvspoof::speaker`로 표준화해 다른 캐시와 의존성을 확인할 수 있다. 다만 원발화→합성/재인코딩 source-family map이 해결됐다는 뜻은 아니다. 21LA는 원래 EBM 실험에서도 관찰한 평가셋이며 새 blind benchmark로 부르지 않는다.

## 실제 실행 기록

## 후속 실험에서 사용할 개수

전체 캐시148,176개는 보존한다. 사용자 요청으로 반복 실험의 기본 입력은 **21LA_pilot20,000개(정상2,000/spoof18,000)**로 고정했다. R2/R3 초기 확인은 그 안의21LA_small2,000개(200/1,800)다. 같은 규모의 DF_pilot/DF_small과 각각 비교하고 T/V 학습·선택 수는 유지한다.

표본 선택 단계에서는 점수·h/z를 읽지 않은 UID hash 순위로 잠갔다. 이후 실제pilot native평가를완료했고EER는0.80%,AUROC는0.9986343889였다. 전체EER1.0535393%와구분한다. 각 실험에 적용할 수와 manifest 읽기는 [실험 명세3.1.1](ebm_frozen_model_experiments_20261105.md#311-신규-캐시-실험의-기본-데이터-수)에 있다. 전체 캐시 API 및 원본파일 hash는 변경하지 않았다.

## 후속 결과의 해석 범위

P1/P2/P3-A의실제T/V학습과두pilot전이평가는이캐시생성이후에수행됐다. dynamic gate의pilot EER는0.80%로native와같았고,static/metric은epoch0 identity가선택됐다. 새선형방향잔차는LL을소폭줄였지만EER는같았다. 전체캐시와pilot은독립된두검증이아니며DF와67화자그룹도공유한다. [최신통합분석](ebm_frozen_all_results_20261105.md)에서지표별판정과진행상태를확인한다. 이파일의11:29유휴상태와“gate학습없음”은캐시생성단계의과거기록이다.
