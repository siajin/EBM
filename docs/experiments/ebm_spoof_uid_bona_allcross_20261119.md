# 스푸프 same UID / 정상 원본 EBM BPL 실험 — 2026-11-19

사용자 요청: 스푸프 BPL만 같은 UID의 long·short로 제한하고, 정상 BPL은 기존 EBM의 전체 교차 쌍 방식을 적용한다. 완료된 정상 all-cross와 정상 same-UID 실험의 클래스별 오류를 먼저 분석하고, 새 GitHub 브랜치에 코드·설정·검증 기록을 올린 뒤 새 학습을 시작한다.

## 목적식과 구현

f(t)=softplus(30(1−t))−0.3, uᵢ와 vᵢ는 같은 입력 항목에서 독립 증강한 long/short 임베딩의 단위 벡터다.

L = L_OC,long + (1/n_s) Σᵢ∈spoof f(uᵢᵀvᵢ) + (1/n_b²) Σᵢ,j∈bona f(uᵢᵀvⱼ).

정상 항은 원본 model/loss.py BPL(alpha=30)의 값·기울기와 FP32/FP64에서 정확히 같다. 같은 UID를 포함하는 모든 long×short 쌍이며 다른 UID만 추리는 방식은 아니다. 두 클래스는 별도 mean과 계수1을 유지한다. 스푸프 쌍 수는 rank별 full/부분 배치에서108/60/108, 정상 쌍 수는144/144/36이다. UID는 화자 ID가 아니라 개별 음성 항목이다. 원본 TrainSet은 동일 항목에서 long/short를 함께 반환하므로 데이터·증강·sampler·배치를 바꾸지 않는다.

OC는 스푸프 pull0.9, 정상 push0.2, alpha20 및 원래 클래스 가중치/전체 N 분모를 유지한다. 중심 단계는 스푸프 long만 사용하며 배율5다. 원래 두 Adam 단계, 동결 XLSR, seed1 새 초기화, global batch240, 50epoch를 유지한다. 학습 중5epoch마다19LA만 평가하며 이후 저장10개 모델이 배치별 XLSR 출력을 공유해21LA/DF를 평가한다.

## 논리·수학 검토

스푸프 same-UID 항은 서로 다른 음성을 직접 같은 위치로 당기는 항을 제거한다. 서로 직교하는 스푸프 벡터라도 각 long/short가 같으면 해당 BPL의 최소값을 달성할 수 있다. 다만 스푸프 OC 응집압력은 남고, 클래스별 점 붕괴도 전체 목적식의 양립 가능한 최소이므로 anti-collapse를 보장하지 않는다. 정상 all-cross와 스푸프 손실은 공유 파라미터를 통해 여전히 충돌할 수 있다. 쌍 수를 줄여도 mean의 클래스 계수는 유지되며 자동으로 loss weight를1/n_s만큼 추가 축소하지 않는다.

정상을−c, 스푸프를+c에 둔 자유 임베딩 구성에서 세 항의 하한이 동시에 실현되고 접선 기울기가0이며 모든 수치가 유한함을 검사했다. 이 양립성은 실제 신경망 최적화·EER 개선을 보장하지 않는다. 직전 정상-UID 모델과는 양쪽 pairing이 모두 바뀌므로 단일 변경 대조군은 정상/스푸프 모두 all-cross였던 v3다.

role_v5는 spoof_bpl_pairing과 두 클래스 reduction을 명시한다. v1~v4 metadata·기존 checkpoint 읽기는 보존한다. 원본 정상 BPL 회귀, 유한차분, 클래스별 short 기울기, 두 CPU rank의 비대칭 부분 배치/중심 동기화/저장 복원을 검사한다. 실제 두 GPU108loader 및1/106/108배치 검증은 본학습의 필수 gate다.

## 학습 전 완료 모델 클래스 오류 비교

두 이전 모델 모두 스푸프 BPL은 all-cross다. 정상 BPL만 전체 교차(v3)와 같은 UID(v4)가 다르다. 각 데이터셋 전체 공식 UID·라벨을 대조했다. 40/50epoch × 두 모델 × 세 데이터셋의12개 EER를 독립 재계산했으며 최대 오차는 약7.4e−15%p다. 추론·재학습 없이 완료 점수만 읽었다.

정상 거부율=정상 중 스푸프로 거부한 비율, 스푸프 통과율=스푸프 중 정상으로 통과한 비율이다. score_bona ≥ threshold면 정상으로 판정한다. 모델별19LA eval에서 실제 가능한 EER 최근접 임계값을 고르고21LA/DF에도 고정한다. 서로 다른 점수척도에 같은 숫자 임계값을 강제하지 않는다. 설명용 eval 기반 임계값으로 운영 검증/독립 보정 성능은 아니다.

### 해석

정상 same-UID는19LA에서는 소폭 개선되고21LA의 정상 거부도 줄지만, 타 도메인 정상 거부율이 여전히 높다. 40epoch21LA에서는 거부율 차이가−0.0405%p에 그치고 스푸프 통과가 증가한다. 같은 UID로 바꾸는 것만으로21LA 열화를 해결했다고 볼 수 없다.

DF는19LA EER 임계값에서 UID의 정상 거부가 늘고 스푸프 통과가 줄었다. 하지만50epoch의 source FAR0.5% 고정 비교에서는 정상 거부도20.6134→20.3174%로 개선된다. 따라서 DF 정상 분포가 일관되게 악화됐다고 단정할 수 없으며 판정 기준과 epoch에 의존한다. 두 방식 모두 타 도메인 오류율의 클래스 편향은 원시 오분류 개수만으로 판단하지 않고 클래스별 비율로 읽어야 한다. 이 결과는 공유 gradient 충돌의 제거 또는 EER 인과관계를 입증하지 않는다.
